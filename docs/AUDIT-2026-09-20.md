# Audit and remediation — 2026-09-20

## Scope

Reviewed the checked-in schema and migrations, authentication callback, provisioning, organizer RPCs, document upload flow, server actions, notification handling, and project checks. This is a repository audit, not a certification or an inspection of the deployed Supabase project's settings/data.

## Fixed in this change

| Severity | Finding | Remediation |
| --- | --- | --- |
| Critical | Self-profile UPDATE allowed role and firm changes. | Restrict authenticated UPDATE to full_name. |
| Critical | SECURITY DEFINER save/submit authorization used nullable inequality, allowing callers without a linked client to bypass the check. | Explicit auth check, null-safe ownership comparison, revoke anonymous/public execution. |
| Critical | Signup trusted caller-controlled firm and role metadata. | Require an admin invitation or server-controlled app metadata; disable signup from the login action. |
| High | Direct response writes bypassed organizer submission locks. | Remove direct response write policies/grants; require the RPC. |
| High | Save and submit could race and overwrite state. | Both RPCs lock the parent organizer before checking status. Document registration uses the same lock. |
| High | Independent foreign keys allowed mixed-tenant organizers/documents. | Add composite constraints and profile-link validation. |
| High | Clients could enumerate all profiles in their firm. | Limit client visibility to self and assigned organizer staff. |
| High | Callback accepted protocol-relative and backslash redirects and logged token-bearing URLs. | Validate local paths; remove URL logging. |
| Medium | File uploads omitted required uploaded_by. | Obtain verified session claims and include the uploader. |
| Medium | Required file questions could never submit; other answer types were unchecked. | Validate types, select membership, nonempty text, and registered storage-backed files. Preserve false and zero as valid values. |
| Medium | Error boundary exposed exception messages. | Generic user message with digest reference. |

## Verification

- `npm test`: two suites, including real SQL execution with PGlite/PostgreSQL and direct role-based denial assertions.
- `npm run lint`, `npm run typecheck`, and `npm run build` pass.
- Dependency installation audit reported zero known vulnerabilities.
- Database tests apply all four migrations. They stub Supabase auth/storage schemas and omit pgcrypto because UUID generation is built into the test engine. They test positive invite provisioning, but do not run the hosted GoTrue invitation API or Storage service.
- Concurrent requests are serialized by SQL row locks; the single-session test harness does not demonstrate multi-session contention.

## Deployment

Apply `supabase/migrations/0004_security_hardening.sql` through the normal migration process before relying on these protections. It is transactional and intentionally fails if existing rows violate the new relationships or if a profile links to multiple clients; investigate and repair those records instead of silently dropping data. No hosted database migration was run during this audit.

Normal client invitations continue through the existing admin invite action. Trusted account creation without an invitation must provide firm_id and role in app_metadata. Confirm this in a staging Supabase project, along with upload, submission, and notification delivery. The tests use Node 22.18+ or Node 24 for native TypeScript imports.

## Remaining findings / next work

- Template creation uses two independent inserts: an item failure can leave an empty template. Move creation into a transaction-backed RPC and validate server-action inputs at runtime.
- The form does not await all pending autosaves/uploads before submission, and overlapping autosaves can complete out of order. Add a serialized save queue and a submit barrier. Database locking prevents post-submit mutations but cannot ensure the latest visible input has reached the server.
- Failed document registration can leave orphan storage objects; add bounded file size/type policies and an authorized cleanup/retry workflow.
- Notification logs contain recipient addresses and subjects; reduce retained personal information. Email delivery is synchronous and has no durable retry queue.
- Some server actions still return raw database messages. Replace these with bounded, user-facing errors and structured server diagnostics.
- Staff review status changes and audit inserts are separate operations; make them atomic.
- Hosted auth rate limits, SMTP, storage configuration, backup/restore, and tenant isolation under the actual Supabase service remain staging checks.
